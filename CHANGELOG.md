# Changelog

## 0.2.24 - Unreleased

- Add an explicit work-duration contract for new jobs and completions. Fresh instances and the job wizard select **Until completion or cancellation**; callers can choose a deadline without a one-hour ceiling.
- Freeze the smallest chosen profile/request deadline at admission. Queue time, pauses and restarts do not renew it. Preserve unversioned callers, existing owner configuration, retained jobs and recovery records under their legacy contract.
- Separate optional HTTP waiting deadlines from execution deadlines. Preserve cancellation by the last ordinary waiter and original-completion retention for opted-in recovery. Refuse chosen deadlines for connected-host execution before admission.
- Expose duration capability and effective profile policies to SDKs and the console. Rearm long timers in safe monotonic slices rather than relying on Node's maximum timer delay.

## 0.2.23 - 2026-10-28

- Allow Claude and Codex workers on one coordinator. Jobs stay provider-agnostic; fair-share dispatches by quota and capacity across CLI types. Cross-CLI failover uses the existing handoff brief.
- Add `bridge cluster init-local-worker` so the coordinator host runs a separate worker process. Pool status includes `eligibleByProvider`; heartbeats may advertise an optional model for observability.
- Keep the diagnostic console optional: register UI routes in a separate module, gate them with `serveUi` / `serve --no-ui`, and drive job pause/resume/cancel/retry plus `token list` from headless CLI JSON commands.
- Resolve only the selected coding CLI on each host. `init-local-worker` defaults to the coordinator's worker; a Codex-only or Claude-only machine never needs the other binary.
- Print the span ASCII banner on TTY `serve` / `daemon start` (still suppressed for JSON cluster commands and `BRIDGE_NO_BANNER`). Refresh cluster docs and quick-start for mixed pools.
- Bump installation, plugin, desktop and OpenAPI metadata to 0.2.23.

## 0.2.22 - 2026-10-28

- Ship the multi-node cluster quota pool: coordinator queue of record, signed worker enrollment, fair-share routing with reserve and RAM/CPU/disk floors, headless `bridge cluster` ops, and didactic cluster documentation.
- Fail over bridge jobs when a sticky home is quota-limited, unhealthy, draining, or offline: pause in-flight work, clear native sticky binding, requeue with a coordinator-owned handoff brief, and auto-reassign to any eligible peer. Fail only after `cluster.maxFailovers` (default 3) with `cluster_failover_exhausted`.
- Prefer the home node while it is eligible; do not transfer native CLI sessions across hosts. Inject the handoff brief on the next claim without `--resume`. Emit `job.cluster_failover` / `job.cluster_reassigned` and expose pool `failovers` / `waitingForFailover` telemetry.
- Refresh installation examples, CLI/plugin/desktop metadata and OpenAPI to 0.2.22.

## 0.2.21 - 2026-10-27

- Accept bounded JSON Schema `pattern` and `patternProperties` constraints, including nullable digest and record-ID fields generated by Pydantic. Enforce the same constraints on returned function arguments and structured output before returning a completion.
- Match accepted patterns with a bundled non-backtracking engine. Preserve Unicode whitespace and dot behavior; reject malformed patterns, lookarounds, backreferences and excessive pattern complexity before durable admission.
- Preserve the original submitted schema, unknown-keyword refusal, local-reference limits and completion-recovery identities. This compatibility change does not submit or replay an existing request.

## 0.2.20 - 2026-10-24

- Preserve recovery-v1 wire and retained-result budgets, original request hashes, known receipts and no-replay behavior. Generic job, image, tool and schema contracts remain separate.

## 0.1.0 — 2026-10-11

Initial private developer release of Firefly Agent Bridge.

- Official Codex ChatGPT and Claude Code subscription workers, with explicit selection and accurate readiness/model discovery.
- Enabled permissions by default, Codex workspace sandboxing, and owner-selected bypass for trusted execution hosts.
- OpenAI-compatible Chat Completions, structured output, caller-owned functions and buffered completion streaming for FireflyAgent and SDK applications.
- Durable SQLite jobs, fenced attempts, native session follow-ups, recovery controls, workflow checkpoints and replayable events.
- Durable command/file/tool audit with observed-provider provenance, metadata views and JSON exports.
- Firefly developer console, native private Claude integrations and authenticated internal release bootstrap.
- Official-schema validated deterministic unsigned MCPB ZIP packaging; vulnerable packaging dependencies removed.
- Complete deterministic, SDK, browser and native-package gates; separate opt-in real subscription smoke.
- Private CI verifies Linux x64, macOS arm64 and Windows x64 before publishing internal GitHub release archives and checksums.

See [verification](docs/verification.md) for evidence boundaries and host-specific acceptance.
